# R3.3 — grain-lock exclusion flag (close-out)

**Milestone:** last unblocked ABF-parity item (`docs/abf-plugin/05-parity/03-processing-parity-requirements.md:64`).
**Branch:** `feat/r3.3-grain-lock-flag`.

## Finding

R3.3 reads: *"Nesting must reject or flag placements that violate a 'grain must run along sheet length' constraint if the user has marked a panel grain-locked"* (ZilInventor-specific enhancement, low priority).

The **reject** half already ships: `packGuillotine.ts` (`chooseOrientationAndRect`, `fits()`) only ever tries the grain-forced orientation for `grain='length'|'width'` panels — a panel that fits only rotated goes to `oversized`, never grain-violating placement. Enforced since `30b9c695`, reinforced by R3.2 (`eb13a307`), locked by existing test `packGuillotine.spec.ts:40-45`.

The **flag** half is the gap: grain-caused exclusions collapse into the generic `'panel-exceeds-sheet'` reason (`packAllMaterials.ts:39-42`), so NestingTab shows the same message for "too big" and "would fit if rotated but grain forbids it".

## Scope calls
