# Native R12 DIMENSION entities in WYSIWYG DXF export

**Date:** 2026-05-27
**Status:** Approved (design); plan pending
**Predecessors:** F10 DXF export (`6996122`), DXF 1:1 export (`5b22932`), all-sheets/zip DXF (`5d234b3`)

## Problem

The WYSIWYG DXF export (`renderDrawingDxf`) currently emits every dimension as **loose
geometry** — extension lines, the dimension line, and a text label drawn directly onto the
`DIMENSIONS` layer as separate `POLYLINE`/`TEXT` entities. When the file is opened in AutoCAD
or Autodesk Inventor, these read as dumb, disconnected lines and text: not a dimension object,
not grip-editable, not re-measurable, not restylable. For the human-reader consumer (a person
opening the drawing in Inventor/AutoCAD), that is a real fidelity gap.

## Goal

Export each supported `DrawingDimension` as a **native DXF `DIMENSION` entity** so it opens as
a single, editable, recomputable dimension object showing the correct measurement.

### Scope decisions (locked during brainstorming)

- **Stay R12 / AC1009.** R12 fully supports `DIMENSION` entities. We do **not** bump to
  R2000/AC1015. (R2000 would be required only for native `HATCH`, which is explicitly out of
  scope — see below.)
- **No manifest bump.** DXF export is read-only; no serialized shape changes (manifest stays
  v19).
- **Consumer:** human reader in AutoCAD/Inventor. (The CAM/CNC geometry consumer is already
  served by the unchanged 1:1 geometry export.)
- **Dimension picture = generated anonymous block** (not regenerate-on-open). Each dimension
  references an anonymous `*D##` block holding the dim's lines/arrows/text, so it renders
  correctly in *any* reader including older Inventor — and remains grip-editable / recomputable.

### In scope — kinds upgraded to native

The dimension kinds the renderer already draws as exploded geometry:

`linear-h`, `linear-v`, `aligned`, `baseline`, `ordinate`, `angular`.

### Out of scope — unchanged

- **Section hatch** stays as fill-stroke line segments (`HatchSegment` p0/p1 pairs). It already
  *looks* filled; native `HATCH` would force an R2000 bump + persisting the cut-face boundary
  polygon (not currently stored) for low marginal value. Explicitly deferred.
- **Section lines + arrows, detail-region borders, balloons, leaders, hole tables, title
  block** — remain exploded geometry, unchanged.
- **`radial` / `diametric` dimensions** — type-defined but **not emitted in DXF today** (silently
  dropped). They remain unsupported in DXF (matches current behavior). Adding native
  radius/diameter dimensions is a clean follow-up, not part of this change.
- **`renderDrawingDxf1to1`** (geometry-only true-mm renderer) — untouched. It emits no
  dimensions.

## Architecture

Three coordinated pieces per dimension, all within the existing R12 structure
(HEADER → TABLES → BLOCKS → ENTITIES → EOF):

1. **`DIMENSION` entity** (ENTITIES section) — carries the dimension's definition points, the
   dim-type flag (group 70), the block reference (group 2), the DIMSTYLE reference (group 3),
   and the measurement text/value (group 1 / computed).
2. **Anonymous block** `*D1`, `*D2`, … (BLOCKS section — currently emitted empty) — contains the
   dimension "picture": the exact extension lines / dimension line / arrowheads / text the
   renderer generates today, in absolute sheet coordinates. This is what readers display, and
   what AutoCAD replaces on a recompute. One block per dimension.
3. **Shared `STANDARD` DIMSTYLE** (new DIMSTYLE table in TABLES) — one entry shared by all
   dimensions, with `DIMTXT` (text height), `DIMASZ` (arrow size), `DIMTAD`, etc. set to match
   the renderer's current visual constants so a recompute reproduces a near-identical picture.

**Design principle:** the dimension picture geometry is generated by the *existing* per-kind
code. This change *wraps* that geometry in a block + entity rather than redrawing it. The
coordinate math stays in the renderer; `dxfWriter` stays coordinate-agnostic.

### `dxfWriter.ts` additions (coordinate-agnostic, pure group-code emission)

- **DIMSTYLE table** emitted in TABLES alongside the existing LTYPE / LAYER tables.
- **`block(name, basePoint, build)`** — emits a `BLOCK` / `ENDBLK` pair and lets the caller emit
  `line` / `polyline` / `circle` / `text` into it (reusing the existing entity emitters).
- **`dimension({ layer, blockName, dimStyle, dimType, defPoints…, text, measurement, … })`** —
  emits the `DIMENSION` entity with the correct R12 group codes.

### `renderDrawingDxf.ts` refactor

The per-kind dimension code (currently emitting loose `POLYLINE`/`TEXT` to the `DIMENSIONS`
layer) is refactored so each dimension:
1. generates its picture geometry into a fresh anonymous block, and
2. emits a `DIMENSION` entity referencing that block + the shared DIMSTYLE.

The existing geometry-generation logic is reused; only the wrapping changes.

### Dimension-kind → DXF dim-type mapping (group code 70)

| App kind   | DXF dim type | Notes                                                       |
|------------|--------------|-------------------------------------------------------------|
| `linear-h` | 0 (rotated)  | rotation angle 0                                            |
| `linear-v` | 0 (rotated)  | rotation angle 90                                           |
| `aligned`  | 1 (aligned)  |                                                             |
| `baseline` | 0 ×N         | each slot → one linear DIMENSION sharing the datum point    |
| `ordinate` | 6            | + X/Y direction bit (group 70 flag)                         |
| `angular`  | 2 / 5        | 2 = two-edge angular; 5 = 3-point/arc angular               |

## Data flow

Unchanged upstream: dimensions are read from `drawing.sheets[].views[]` dimension data and their
`PointRef`s are resolved to absolute 2D sheet coordinates by the *existing* resolution logic
(the same logic that today positions the loose lines). The only change is downstream of that
resolution: emit `DIMENSION` + block instead of loose lines.

Y-flip convention (`dxfY = sheetH - svgY`) is preserved — applied to all block geometry and to
the DIMENSION definition points identically.

## Error handling

- `dxfWriter.fmt()` NaN/Infinity/-0 guard continues to apply to every emitted coordinate
  (including DIMENSION def points and block geometry).
- A dimension whose `PointRef`s fail to resolve is skipped exactly as today (no entity emitted),
  not emitted as a malformed DIMENSION.
- Block names are unique per dimension (`*D1`, `*D2`, …) to avoid name collisions.

## Testing & verification

TDD, red → green per slice.

- **`dxfWriter` unit:** DIMSTYLE table present in TABLES output; `block()` round-trips its
  geometry inside a BLOCK/ENDBLK pair; `dimension()` emits the expected group codes (type, block
  ref, dimstyle ref, def points, text).
- **`renderDrawingDxf` unit:** for each in-scope kind, exactly one `DIMENSION` entity and one
  anonymous block are emitted; block count == in-scope dimension count; the picture geometry now
  lives inside the block (existing assertions expecting loose lines on the `DIMENSIONS` layer are
  updated to the new structure — an expected, intentional regression).
- **e2e (real Chromium, parse-back):** create a drawing carrying dimensions of multiple kinds,
  export DXF, parse it back, assert native `DIMENSION` entities exist with the correct dim types
  and measurement values, and that one anonymous block accompanies each. Console-clean.
- **perf probe:** a `T63*` probe confirming the dimension-heavy render+emit stays well under
  budget (reuses the existing perf harness pattern).

### Verification limitation (CLAUDE.md §6)

We can structurally validate the output against the R12 `DIMENSION` group-code spec and
round-trip it through the test parser, but we **cannot open the file in AutoCAD or Inventor 2012
in this environment**. "Opens cleanly and shows as an editable dimension in Inventor 2012"
remains **written-but-unverified** and is flagged for the user's manual smoke test on their box.

## Risks

1. **Hand-rolled DIMENSION correctness without an AutoCAD round-trip.** Mitigated by strict
   group-code structural assertions + parse-back; residual risk owned by the manual-smoke caveat.
2. **DIMSTYLE / block-geometry mismatch.** If DIMSTYLE constants drift from the block's actual
   geometry, a user "recompute" in AutoCAD would visibly shift the dimension. Mitigated by
   deriving DIMSTYLE values from the same constants the renderer uses.
3. **Test churn.** Existing tests asserting the old exploded-line structure on the `DIMENSIONS`
   layer must be rewritten to the new structure. Bounded and expected.

## Out-of-scope follow-ups (not this change)

- Native `radial` / `diametric` dimensions.
- Native `HATCH` (requires R2000 + persisting cut-face boundary polygon).
- R2000/AC1015 version bump.
- Native dimensions in the 1:1 export (it currently emits none by design).
