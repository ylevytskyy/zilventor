# M2.3 — Per-Panel Shop Labels (PDF) — Design

**Milestone:** M2 (manufacturing output / "ABF-plugin parity"), third and final slice after
M2.1 (per-panel manufacturing DXF) and M2.2 (nesting/sheet-layout DXF). Completes M2.
**Branch:** `feat/m2.3-panel-labels` (off `master` `8d46bdd1`).
**Date:** 2026-06-23.

## 1. Goal

A **"Export Labels (PDF)"** button on the Furniture tab produces a printable A4 PDF of shop
labels — **one label per physical panel** — each showing item#, part name, material, dimensions
(L×W×T), a mini panel diagram (grain arrow + banded-edge marks), and a scannable **QR code**.

This is the per-panel shop-label half of the manufacturing-audit P0 (#2/#3, ABF parity): after
M2.1/M2.2 give the cut/nesting geometry, M2.3 gives the operator a sticker per physical panel so
each cut piece is identifiable and scannable at assembly.

## 2. Locked product decisions

(All four chosen during brainstorming; recommendations accepted.)

1. **Output = PDF label sheet** (not DXF). Labels are printed/stuck on panels, not CNC-cut.
   Uses `jspdf@4.2.1` (already a dependency).
2. **QR code** on each label (add `qrcode` dep). 2D, dense, embeds as filled rects drawn directly
   from the bit matrix — no canvas, deterministic, unit-testable.
3. **One label per physical panel** — iterate each cut-list row's physical copies; each label shows
   "copy k/N".
4. **Text + mini panel diagram** — text fields PLUS a small rectangle with a grain arrow and
   thickened edges where edge-banding is applied (edge codes shown visually).

## 3. Data sources (verified, see `aggregateCutListRecursive`)

No nest dependency — labels come straight from the assembly cut-list.

- **`aggregateCutListRecursive(activeAssembly, …)`** → `CutListResult { rows: CutListRow[] }`
  (`packages/app/src/assembly/walkers/aggregateCutListRecursive.ts`). Groups identical panels by
  `cutListRowKey` and records one `componentPathKeys` entry per physical copy.
- **`CutListRow`** (`packages/shared/src/cutListRow.ts`):
  ```ts
  type CutListRow = {
    rowKey: string;
    itemNumber: number;            // stable, user-reorderable
    qty: number;                   // # of physical copies of this type
    length: number; width: number; thickness: number;   // mm
    materialId: MaterialId; materialName: string;
    grain: GrainDirection;         // 'length' | 'width' | 'none'
    edgeBands: { [K in PanelEdgeKey]: CutListEdgeBandCell };  // all 4 edges present
    partPath: string; partName: string;
    componentPathKeys: string[];   // length === qty (one per physical copy)
    oversize?: { lengthMm; widthMm };
  };
  ```
- **`PanelEdgeKey`** = `'front' | 'back' | 'left' | 'right'`; **`CutListEdgeBandCell`** =
  `{ materialId, materialName, thickness } | null` (null = no band on that edge)
  (`packages/shared/src/panel-feature.ts`, `cutListRow.ts`).
- **`GrainDirection`** = `'length' | 'width' | 'none'` — which axis grain runs along; no angle.

## 4. Architecture — 5 units

Mirrors the M2.1/M2.2 structure (pure renderer + flatten helper + command + ribbon button).

### 4.1 `renderLabelsPdf(labels: PanelLabel[], opts?): Uint8Array`
`packages/app/src/drawing/renderLabelsPdf.ts`. Builds the jspdf document (`{ unit:'mm', format:'a4',
orientation:'portrait' }`), lays labels on a grid (default **2 columns × 5 rows = 10 labels/page**;
constants for cols/rows/margins so the grid is one place to tune), calls `pdf.addPage()` on overflow.
Returns `new Uint8Array(pdf.output('arraybuffer'))`.

- Pure layout helper **`labelCellRect(index, opts): { x, y, w, h, page }`** — index→cell geometry +
  0-based page. Unit-tested directly (pagination math is the testable core; the jspdf draw calls are
  smoke-tested).
- Per label cell: draw text block, then `drawLabelDiagram`, then `drawQr`.

### 4.2 `qrMatrix(text)` + `drawQr(pdf, matrix, x, y, sizeMm)`
`packages/app/src/drawing/qr.ts`. `qrMatrix` wraps `QRCode.create(text, { errorCorrectionLevel:'M' })`
→ returns `{ size: number, data: Uint8Array }` (`modules`). `drawQr` iterates the matrix and emits a
filled `pdf.rect(..., 'F')` for each **dark** module (`data[row*size+col] === 1`), module size =
`sizeMm / matrix.size`. Quiet zone left to the cell padding. Pure & deterministic — a fixed input
yields a fixed matrix; tests assert `size` and that the dark-rect count equals the matrix popcount.

### 4.3 `drawLabelDiagram(pdf, label, rect)`
`packages/app/src/drawing/renderLabelsPdf.ts` (or a sibling). Draws a panel rectangle scaled to fit
`rect` with aspect ratio `length:width` (length horizontal/+X, width vertical/+Y). Overlays:
- **Grain arrow:** `grain==='length'` → horizontal arrow; `grain==='width'` → vertical arrow;
  `grain==='none'` → no arrow.
- **Banded edges:** for each `PanelEdgeKey` whose `edgeBands[key]` is non-null, draw a thick line on
  that diagram side and the edge letter (`F`/`B`/`L`/`R`).

> **⚠ LOAD-BEARING — edge→diagram-side mapping.** Which physical diagram side each of
> `front/back/left/right` maps to MUST be derived from the actual panel edge-geometry convention in
> `packages/shared/src/panel-feature.ts` (how `EdgeBand` is applied to a `PanelSpec`), **not guessed**,
> and **pinned with a unit test** — exactly the discipline that caught the M2.1 groove-centering
> (`pos±w/2`) and M2.2 rotated-footprint bugs. Likewise the **grain arrow axis** is pinned with a test.
> Treat the mapping as unknown until grounded in code during planning.

### 4.4 `buildPanelLabels(cutListResult: CutListResult): PanelLabel[]`
`packages/app/src/drawing/buildPanelLabels.ts` (pure). Flattens each `CutListRow` into `qty` labels:

```ts
type PanelLabel = {
  itemNumber: number;
  partName: string;
  materialName: string;
  length: number; width: number; thickness: number;
  grain: GrainDirection;
  edges: { front: boolean; back: boolean; left: boolean; right: boolean };  // banded?
  copyIndex: number;   // 1-based
  copyCount: number;   // === row.qty
  qrPayload: string;
};
```

`qrPayload` is a compact delimited UTF-8 token, e.g. `Z|<item>|<copy>/<qty>|<L>x<W>x<T>|<material>`.
(QR byte mode handles UTF-8 — material names are **not** subject to the DXF ASCII-only limitation.)
Label order: rows in cut-list order, copies `1..qty` within each row.

### 4.5 `ExportPanelLabelsCommand` + ribbon button
`packages/app/src/commands/ExportPanelLabelsCommand.ts`. Gathers the cut-list from the active
assembly via the **same input path M2.1's panel-manufacturing export uses** (the cut-list hook /
`aggregateCutListRecursive` call site — ground the exact glue during planning), then
`buildPanelLabels` → `renderLabelsPdf` → `triggerDownload` (`packages/app/src/nesting/triggerDownload.ts`,
`showSaveFilePicker` → `<a download>` fallback). Suggested filename `labels.pdf`.

Button in `FurnitureTab.tsx` manufacturing/nesting ribbon panel (next to the M2.1/M2.2 export
buttons), gated on `!activeAssembly` (labels need an assembly cut-list, **not** a computed nest).
i18n key `ribbon.furniture.exportLabels` in **en + uk**.

## 5. Out of scope (YAGNI)

- Configurable label-stock presets (Avery sizes) — ship one sensible A4 grid; constants are
  centralized so a follow-up can add presets.
- Per-edge band material/thickness text on the label (only *which* edges are banded is shown).
- Linear/Code128 barcodes (QR chosen).
- DXF label output.
- No document/manifest schema change — pure export feature, **NO manifest bump**.

## 6. Dependencies

Add to `packages/app/package.json`: `qrcode` (runtime) + `@types/qrcode` (dev). No other deps.

## 7. Testing strategy (TDD slices)

Each slice is red→green; per-task `pnpm typecheck` gate after every task (M2.1 lesson).

1. **qr** — `qrMatrix` deterministic for a fixed string (assert `size`, a known module count);
   `drawQr` emits filled-rect count == matrix popcount.
2. **buildPanelLabels** — a `CutListResult` with rows qty=2 and qty=3 → 5 labels with correct
   `copyIndex`/`copyCount`, item numbers, material, dims, and `edges` flags.
3. **edge→diagram-side mapping** — pinned test (panel banded on specific edges → assert which
   diagram sides drawn thick), grounded in `panel-feature.ts`.
4. **grain arrow** — pinned test (length→horizontal, width→vertical, none→absent).
5. **`labelCellRect`** — pagination math (index 0..9 page 0; index 10 page 1; coordinates).
6. **`renderLabelsPdf`** — smoke: output starts with `%PDF`, page count correct for >10 labels.
7. **e2e (Playwright, real Chromium)** — click "Export Labels" → intercept the download →
   PDF bytes non-empty, `%PDF` header, expected page count; 0 console/page errors.
