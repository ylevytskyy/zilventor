# Drawing F2.1 — Rectangular Detail Region

**Status:** Approved (design) — 2026-05-25
**Extends:** Drawing F2 (Detail views) + F2.4 (Edit Detail Region). No kernel involvement.
**Manifest:** **v18 → v19** (migration backfills `kind:'circle'` onto existing `regionParent`).

---

## 1. Summary

Detail views can magnify an **axis-aligned rectangular** sub-region of a parent
drawing view, in addition to the existing circular region. Same magnify-and-place
flow, same pure-2D pipeline (no kernel call): the parent's projected `Edge2D`s are
clipped against the region, translated (region center → origin), and scaled by the
detail factor.

Locked decisions (from brainstorming):

- **Picker:** corner-to-corner marquee — click one corner, drag to the opposite
  corner. Normalized to center + width + height on commit.
- **Shape selection:** two ribbon buttons — "Detail" (circle) and "Detail (Rect)".
- **Editing:** F2.4 Edit Detail Region extended to rect — body drag moves center,
  **4 corner handles** resize (opposite corner fixed).
- **Orientation:** axis-aligned only. Rotated rects are a non-goal.

## 2. Background / current state

- `RegionParent` is **flat circle-only** today
  (`packages/shared/src/drawing/types.ts:184`):
  `{ readonly center: Vec2; readonly radiusMm: number }`. It is the
  `regionParent` field of `DetailView` (`kind:'detail'`, `types.ts:193`). **Not a
  discriminated union yet** — that is the core change.
- Clip pipeline (`packages/shared/src/drawing/`): `clipLineToCircle` →
  `clipPolylineToCircle` → `clipEdgesToCircle(edges, center, radius)` (preserves
  `id/kind/sourceFaceIds`, suffixes survivors `_clip0`, `_clip1`, …);
  `projectDetailView(input)` orchestrates clip → translate (center→origin) → scale
  by detail factor → recompute bbox. Degenerate-safe: a miss yields `[]` edges and
  a `{0,0,0,0}` bbox (no throw).
- `fingerprintDetailView(parentFp, regionParent, scale)`
  (`packages/shared/src/drawing/fingerprint.ts:96`) hashes `center.x`, `center.y`,
  `radiusMm`, `scale.{num,den}` via djb2 (`.toFixed(3)` rounding).
- Commands (`packages/app/src/commands/`): `AddDetailViewCommand` builds
  `regionParent:{center,radiusMm}`, sets **both** `activeDocument` AND
  `activeDrawing`; `EditDetailRegionCommand` carries `prevRegion`/`newRegion`
  (`Region = {center,radiusMm}`) and delegates to `reprojectDetailRegion` (pure
  helper, imports only `@zilventor/shared`, calls `projectDetailView` +
  `fingerprintDetailView`).
- ToolMode (`packages/app/src/drawing/toolMode.ts`): `'detail'` mode stages
  `pickRegionCenter → pickRegionRadius → pickDrop`; `'editDetailRegion'` mode with
  `EditDetailRegionToolState` (`idle` / `draggingCenter` / `draggingRadius`),
  `Region = {center,radiusMm}`.
- Renderers — every circle drawn from `regionParent`:
  - Live: `DetailRegionOverlay.tsx` (callout on parent), `ViewElement.tsx`
    (`data-role="detail-border"` in detail-local space),
    `DetailRegionEditHandles.tsx` (body circle + east radius square).
  - Export: `renderDrawingSvg.ts` — `detail-border` circle at origin (`~L185`) +
    `detail-callout-label` circle on parent (`~L217`); `renderDrawingPdf.ts`
    parallel jsPDF circle; `renderDrawingPngForSheet.ts` delegates to SVG.
- Constants (`packages/app/src/drawing/drawingConstants.ts`):
  `MIN_DETAIL_RADIUS_MM = 1.0`.

## 3. Data model

`RegionParent` becomes a discriminated union (`packages/shared/src/drawing/types.ts`):

```ts
export type RegionParent =
  | { readonly kind: 'circle'; readonly center: Vec2; readonly radiusMm: number }
  | { readonly kind: 'rect';   readonly center: Vec2; readonly widthMm: number; readonly heightMm: number };
```

- All coordinates in **parent-local mm (pre-scale)**, matching circle today.
- Rect is **center-anchored** (center + full `widthMm`/`heightMm`), not
  corner-anchored. The marquee picker collects two corners `c1`,`c2` and on commit
  computes `center = midpoint(c1,c2)`, `widthMm = |c1.x − c2.x|`,
  `heightMm = |c1.y − c2.y|`. Center anchoring lets the move-drag math be shared
  with circle.
- The `Region` type used by the ToolMode + `EditDetailRegionCommand` /
  `reprojectDetailRegion` is unified to **be** `RegionParent` (the same union).

### 3.1 Migration v18 → v19

Existing saved files store `regionParent:{center,radiusMm}` with **no `kind`**.
`migrations[18]` walks documents → drawings → sheets → views; for every
`kind:'detail'` view whose `regionParent.kind` is absent, sets
`regionParent = { kind:'circle', center, radiusMm }`. `ProjectFile` union gains
`| 19`. All existing migration-test fixtures that assert `toBe(18)` for the latest
version cascade to `19`.

Rationale for a real migration (vs runtime-default absent `kind` to circle):
matches the established codebase pattern (F2 did v15→v16 for `DetailView`), keeps
the discriminated union honest so exhaustiveness `switch`es are sound, and avoids
scattering `?? 'circle'` normalization across read sites.

## 4. Clip pipeline

New rect functions alongside the circle ones (`packages/shared/src/drawing/`):

- `clipLineToRect(p0, p1, rect) → Segment[]` — **Liang–Barsky** against the
  axis-aligned box `[cx − w/2, cx + w/2] × [cy − h/2, cy + h/2]`. Returns `[]` or a
  single surviving sub-segment. Handles: both inside; both outside, no crossing;
  both outside, crossing (enters+exits); one in / one out; collinear with an edge;
  endpoint exactly on a boundary; zero-length segment; segment touching a corner.
- `clipPolylineToRect(points, rect) → Segment[]` — composes `clipLineToRect` over
  consecutive pairs.
- `clipEdgesToRect(edges, rect) → Edge2D[]` — mirrors `clipEdgesToCircle`:
  preserves `id/kind`, conditional-spreads `sourceFaceIds` (for
  `exactOptionalPropertyTypes`), suffixes survivors `_clip0`/`_clip1`/….
- `projectDetailView` **dispatches on `regionParent.kind`** for the clip step
  (`circle → clipEdgesToCircle`, `rect → clipEdgesToRect`). The translate
  (`center → origin`) + scale steps are **shared** — both shapes are center-based.

Liang–Barsky is exact for axis-aligned boxes and avoids the Sutherland–Hodgman
polygon machinery (overkill for line segments). Curved edges are already
tessellated to polylines upstream (same as the circle path), so no arc-vs-rect
analytic intersection is needed.

## 5. Fingerprint

`fingerprintDetailView` accepts the `RegionParent` union and branches on `kind`:

- `circle` → `kind`, `center.x`, `center.y`, `radiusMm`, `scale.num`, `scale.den`.
- `rect`   → `kind`, `center.x`, `center.y`, `widthMm`, `heightMm`, `scale.num`,
  `scale.den`.

`kind` joins the payload so a circle and a rect with the same bounding box never
collide. Same djb2 + `.toFixed(3)` rounding.

---

## 6. Commands

- `AddDetailViewCommand` carries a `RegionParent` union (built by the ToolMode) and
  writes it onto the new `DetailView`. Continues to set **both** `activeDocument`
  AND `activeDrawing` (F6 gotcha — `DrawingCanvas` subscribes to `activeDrawing`).
- `EditDetailRegionCommand` + `reprojectDetailRegion` carry the union as
  `prevRegion`/`newRegion` and pass it straight to the now-union-aware
  `projectDetailView` + `fingerprintDetailView`. Undo correctness still rides the
  explicit `prevRegion` (the live drag already left the store at `newRegion`).
- A rect cannot be edited into a circle or vice-versa through these commands;
  `kind` is fixed at creation (kind-conversion is a non-goal, tracked as F2.1.x).

---

## 7. ToolMode

- New **`'detailRect'`** mode, stages
  `idle → pickFirstCorner → pickSecondCorner → pickDrop`. On `pickSecondCorner`
  completion it computes center/width/height, clamps each dimension to a new
  `MIN_DETAIL_RECT_MM` (default `1.0`). `pickDrop` dispatches `AddDetailViewCommand`
  with `{kind:'rect',…}`. ESC mirrors the circle mode's double-press
  (first resets stage, second exits).
- Existing **`'detail'`** mode now emits `{kind:'circle',…}` (otherwise unchanged).
- **`'editDetailRegion'`** extended: the region state is the union. Branch on
  `kind`:
  - `circle`: body drag → move center; east square → resize radius (unchanged).
  - `rect`: body drag → move center; **4 corner handles** → resize. Dragging a
    corner keeps the **opposite** corner fixed and recomputes
    `center`/`widthMm`/`heightMm`; clamp to `MIN_DETAIL_RECT_MM`.
  `editDragStart`/`editDragMove`/`editDragEnd` gain rect arms; `editDragMove`
  returns the updated `RegionParent`.

## 8. Renderer paths (parallel rect branches — same batch, grep-parity gate)

Every circle drawn from `regionParent` gets a rect sibling. Branch on
`regionParent.kind`:

| Path | File | Circle today | Rect to add |
|------|------|--------------|-------------|
| Live callout on parent | `DetailRegionOverlay.tsx` | `<circle>` | `<rect>` outline |
| Live detail border | `ViewElement.tsx` (`detail-border`) | `<circle>` at origin | `<rect>` centered at origin (scaled w×h) |
| Live edit handles | `DetailRegionEditHandles.tsx` | body circle + east square | body rect + 4 corner squares |
| Export detail border | `renderDrawingSvg.ts` (`~L185`) | `<circle r>` | `<rect>` (scaled w×h, centered) |
| Export callout | `renderDrawingSvg.ts` (`~L217`) | `<circle>` | `<rect>` |
| Export PDF | `renderDrawingPdf.ts` | jsPDF `circle` | jsPDF `rect` |
| Export PNG | `renderDrawingPngForSheet.ts` | (delegates to SVG) | automatic |

`data-role` attributes (`detail-border`, `detail-callout-label`) are reused on the
rect elements. A grep-parity check (`detail-border` / `detail-callout-label` appear
with a rect branch in every file that has a circle branch) gates "done".

## 10. Testing (TDD slices) + verification

- `clipLineToRect`: the full Liang–Barsky case table from §4 (each its own slice,
  red→green).
- `clipEdgesToRect`: preserves `id/kind/sourceFaceIds`, `_clipN` suffixing, miss → `[]`.
- `projectDetailView` rect branch: clip → translate → scale → bbox; degenerate miss → `{0,0,0,0}`.
- `fingerprintDetailView` rect: distinct from a same-bbox circle; sensitive to
  `widthMm`/`heightMm`.
- **Migration v18→v19**: a v18 fixture with a circle detail backfills
  `kind:'circle'`; idempotent on already-v19 data.
- `AddDetailViewCommand` rect: apply writes rect + projection; revert removes; sets
  both `activeDocument` + `activeDrawing`.
- `EditDetailRegionCommand` rect: move (center) + corner-resize; undo via explicit
  `prevRegion`.
- ToolMode: `detailRect` state machine (two corners → normalized region);
  `editDetailRegion` rect arms (corner math, opposite-corner-fixed, min clamp).
- Render parity: both live + export emit a rect border + rect callout for a rect
  region (grep-parity + DOM/string assertions).
- **E2E (T-6-16)**: create a rect detail via the real bus, then edit it (move +
  resize a corner) via real `bus.execute`/`bus.undo`; assert clipped geometry +

- **Perf**: rect-clip 100-iter p95 within budget (reuse the detail perf harness /

## 11. Non-goals (F2.1.x follow-ups)

- Rotated rectangles (rotation field + oriented-box clip + rotate handle).
- Converting an existing detail between circle and rect (`kind` is fixed at create).
- Numeric region entry (dialog) and snap-to-parent-geometry (inherited F2.4.E).
- Multi-region rect detail with a shared label (F2.6 territory).
