# Drawing F2.4 — Edit Detail Region (drag handles for detail center/radius)

**Status:** Approved (design) — 2026-05-25
**Extends:** Drawing F2 (Detail views). No kernel involvement.
**Manifest:** No version bump (stays v18). No new persisted field.

---

## 1. Summary

A user can edit an **existing** detail view's source region by dragging handles on
its callout circle (the circle drawn on the *parent* view):

- **Drag the circle body** → relocates the region center on the parent.
- **Drag the east-edge square handle** → resizes the region radius.

Each completed drag gesture is **one undoable command**
(`EditDetailRegionCommand`). During the drag the magnified detail re-clips **live**
(every pointer-move, rAF-throttled) so the user sees the resulting geometry update
in real time. The pipeline is the existing pure-2D `projectDetailView` →
`clipEdgesToCircle` (sub-millisecond; no kernel call).

This is the **first drawing-layer drag→command interaction** in the codebase.
`MoveViewCommand` / `MoveDrawingDimensionCommand` exist but have no UI caller; F2.4
establishes the pointerdown→live-preview→pointerup→commit pattern.

## 2. Background / current state

- `DetailView` is a discriminated-union member of `DrawingView`
  (`packages/shared/src/drawing/types.ts`), `kind: 'detail'`. The source region is
  `regionParent: { center: Vec2; radiusMm: number }` in **parent-local mm
  (pre-scale)**. Clipped geometry lives in
  `projection?: { visibleEdges; hiddenEdges; bbox }`. `inputFingerprint` is a djb2
  hash of parent fingerprint + regionParent + scale.
- Creation flow: `AddDetailViewCommand`
  (`packages/app/src/commands/AddDetailViewCommand.ts`) resolves the parent, calls
  `projectDetailView`, computes `fingerprintDetailView`, and writes the view via
  `useAppStore.setState({ activeDocument, activeDrawing })`.
- Clip pipeline: `projectDetailView(input)`
  (`packages/shared/src/drawing/projectDetailView.ts:84`) →
  `clipEdgesToCircle(edges, center, radius)`
  (`packages/shared/src/drawing/clipEdgesToCircle.ts:105`). **Degenerate-safe:** a
  region that misses all geometry yields `[]` edges and `computeBbox` returns
  `{0,0,0,0}` (projectDetailView.ts:65) — no throw.
- Callout circle renders in **both** paths from `regionParent`:
  - Live canvas: `DetailRegionOverlay`
    (`packages/app/src/drawing/DetailRegionOverlay.tsx`), sheet transform at lines
    20–23: `cx = parent.positionMm.x + center.x * parentScale`,
    `r = radiusMm * parentScale`.
  - Export: `renderDetailCalloutGroups()` in
    `packages/app/src/drawing/renderDrawingSvg.ts:196`.
- Detail content (magnified edges) renders via `ViewElement` (live) and
  `renderViewGroup()` (export), both reading `view.projection`.
- Tool-mode state machines: `packages/app/src/drawing/toolMode.ts` — a Zustand store
  with a per-tool sub-state machine + actions (see `DetailToolState`,
  `SectionToolState`, `SteppedSectionToolState`).
- Pointer handling today: `DrawingCanvas.tsx` is a single SVG with an `onClick`
  handler for click-based tool flows + middle-button pan. **No `onPointerDown` on
  individual elements yet.**

## 3. Goals / non-goals

**Goals**
- Drag-to-move center; drag-to-resize radius, on an existing detail's parent callout.
- Live WYSIWYG re-clip during the gesture.
- One undo entry per gesture; redo restores.
- Min-radius floor; center unconstrained (empty detail tolerated).

**Non-goals (deferred)**
- Editing detail **scale** (already covered by `EditViewScaleCommand`) or **drop
  position** (`MoveViewCommand`) — out of scope.
- Rectangular detail regions (F2.1).
- Multi-handle / rotation / non-circular regions.
- Numeric entry of center/radius (dialog) — drag only.
- Snapping to parent geometry.

---

## 4. Design decisions (locked via brainstorming)

| Axis | Decision |
|---|---|
| Activation | New `ToolMode 'editDetailRegion'`; ribbon button enters it; handles show on every detail callout while in the mode. |
| Live behavior | Re-clip on **every** pointer-move (rAF-throttled), full content updates live. |
| Handles | Drag circle **body** to move center; **one** east-edge (3 o'clock) square handle to resize radius. |
| Constraints | `MIN_DETAIL_RADIUS_MM` floor on resize; center free; empty clip tolerated. |
| Undo | One `EditDetailRegionCommand` per gesture, carrying explicit `prevRegion` + `newRegion`. |
| Commit mechanism | **Approach A** — transient live store-writes during drag; single command dispatched on `pointerup`. |

## 5. Architecture

### 5.1 Shared re-projection helper (reuse)

No new shared code required — `projectDetailView` + `fingerprintDetailView` already
do exactly what's needed. Both the command and the live-preview action call them with
the **same** inputs as `AddDetailViewCommand` (parent view + its projection, the
detail's existing `scale`, the detail's existing `showHidden`).

Define one app-layer pure helper to avoid duplication:

```ts
// packages/app/src/commands/reprojectDetailRegion.ts
import { projectDetailView, fingerprintDetailView } from '@zilventor/shared';
import type { DetailView, DrawingView } from '@zilventor/shared';

/** Recompute a DetailView's projection + fingerprint for a new region.
 *  Pure: returns a new DetailView; does not touch the store. */
export function reprojectDetailRegion(
  detail: DetailView,
  parentView: DrawingView,            // must have .projection populated
  region: { center: { x: number; y: number }; radiusMm: number },
): DetailView;
```

Used by both `EditDetailRegionCommand.apply/revert` and the live-preview store action.

### 5.2 EditDetailRegionCommand

```ts
// packages/app/src/commands/EditDetailRegionCommand.ts
export type EditDetailRegionOpts = {
  sheetId: string;
  detailViewId: string;
  prevRegion: { center: { x: number; y: number }; radiusMm: number };
  newRegion:  { center: { x: number; y: number }; radiusMm: number };
};

export class EditDetailRegionCommand implements Command {
  readonly name = 'EditDetailRegion';
  constructor(private readonly opts: EditDetailRegionOpts) {}
  async apply(): Promise<void>;   // write newRegion via reprojectDetailRegion + setState
  async revert(): Promise<void>;  // write prevRegion via reprojectDetailRegion + setState
}
```

- Both `apply` and `revert` resolve the active drawing → sheet → detail view + its
  parent (`parentViewId`), call `reprojectDetailRegion`, and replace the detail view
  in-place via `sheets.map(... views.map(v => v.id === detailViewId ? next : v))`,
  then `useAppStore.setState({ activeDocument, activeDrawing })`. Mirrors
  `AddDetailViewCommand` write shape.
- **Idempotent on apply:** since the live drag already left the store at `newRegion`,
  re-applying `newRegion` is a visual no-op but pushes the correct undo entry. Undo
  correctness comes from the explicit `prevRegion`, not a store snapshot.
- Guard: if detail view, its parent, or `parent.projection` is missing → no-op
  (defensive; the mode only activates with valid details).

### 5.3 ToolMode extension

Add to `packages/app/src/drawing/toolMode.ts`:

```ts
export type ToolMode = ... | 'editDetailRegion';

export type EditDetailRegionToolState =
  | { stage: 'idle' }                                   // handles shown on all detail callouts
  | { stage: 'draggingCenter'; detailViewId: string;
      startRegion: Region; anchor: { x: number; y: number };   // parent-local pointer-down point
      center: { x: number; y: number } }                       // live center
  | { stage: 'draggingRadius'; detailViewId: string;
      startRegion: Region; radiusMm: number };                 // live radius (center fixed = startRegion.center)
// Region = { center: {x,y}; radiusMm: number }
```

Store fields + actions:
- `editDetailRegionState: EditDetailRegionToolState` (init `{stage:'idle'}`), reset in `reset()`.
- `enterEditDetailRegionMode()` → `{ mode:'editDetailRegion', editDetailRegionState:{stage:'idle'} }`.
- `editDragStart(detailViewId, handle:'center'|'radius', startRegion, anchor)` → set the
  matching dragging stage. For `center`, store `anchor` (the parent-local pointer-down
  point) so dragging preserves the grab offset; for `radius`, anchor is ignored.
- `editDragMove(point)` (point in parent-local mm) → returns the live region:
  - **center drag** — delta-based, no jump on grab:
    `center = { startRegion.center.x + (point.x − anchor.x),
                startRegion.center.y + (point.y − anchor.y) }`.
  - **radius drag** — center fixed at `startRegion.center`:
    `radiusMm = max(hypot(point − startRegion.center), MIN_DETAIL_RADIUS_MM)`.
  The caller pushes the returned region into the live-preview store action.
- `editDragEnd(onDispatch: (prevRegion, newRegion) => void)` → if dragging, call
  `onDispatch(startRegion, liveRegion)` then return to `{stage:'idle'}`.
- `editDetailCancel()` → first Esc while dragging: revert live preview to
  `startRegion` and go idle; second Esc (idle): exit mode. (Mirror `detailCancel`
  two-stage Esc.)

### 5.4 Handle rendering + pointer wiring

A new overlay `DetailRegionEditHandles`
(`packages/app/src/drawing/DetailRegionEditHandles.tsx`), rendered by `DrawingCanvas`
**only** when `mode === 'editDetailRegion'`, once per detail view:

- A transparent-fill `<circle>` matching the callout (cx, cy, r from
  DetailRegionOverlay's transform) with `onPointerDown` → start a **center** drag,
  passing the parent-local pointer-down point as `anchor`.
- A small `<rect>` square handle at `(cx + r, cy)` with `onPointerDown` → start a
  **radius** drag. Handle size in sheet-mm, scaled by `zoom` for constant screen size.
  Because the body circle also captures center drags, the radius handle's
  `onPointerDown` must `stopPropagation` so it is not shadowed by the body.
- Pointer move/up are bound on `pointerdown` (window listeners or
  `setPointerCapture` on the canvas), removed on `pointerup`. On move: convert screen
  → sheet → parent-local mm and feed `editDragMove`, then call the live-preview store
  action. On up: call `editDragEnd((prev, next) => bus.execute(new EditDetailRegionCommand(...)))`.
- **Coordinate inversion** (invert DetailRegionOverlay.tsx:20–23):
  `parentLocal = { x: (sheetPt.x − parent.positionMm.x) / parentScale,
                   y: (sheetPt.y − parent.positionMm.y) / parentScale }`.
  Reuse `DrawingCanvas`'s existing screen→sheet conversion (the same one `onClick`
  uses).
- **rAF throttle:** coalesce multiple pointermove events into one re-clip per frame.

### 5.5 Live-preview store action

```ts
// in useAppStore (or a thin drawing slice)
updateDetailRegionLive(sheetId, detailViewId, region): void
```

Recomputes the detail via `reprojectDetailRegion` and writes it with
`setState({ activeDocument, activeDrawing })` **without** touching the command bus.
This is the transient WYSIWYG write; undo correctness is owned by the command
dispatched on `pointerup`. (Mirrors the assembly B3 drag precedent of direct
store mutation during a gesture.)

### 5.6 Ribbon

Add an "Edit Detail Region" button to the drawing ribbon beside the existing Detail
button. Click → `enterEditDetailRegionMode()`. Disabled (or no-op) when the active
sheet has zero detail views.

### 5.7 Constants

```ts
export const MIN_DETAIL_RADIUS_MM = 1.0;  // parent-local mm; prevents degenerate clip
```
Location: alongside the edit overlay or in a drawing constants module. Tunable.

## 6. Renderer-parity note (why the two-path gotcha does NOT bite)

Editing changes only `regionParent` (+ recomputed `projection`/`inputFingerprint`).
The callout circle and the magnified content already render in **both** the live
canvas and the SVG export from those fields, so edits propagate to export
**automatically**. The drag **handles** are a live-canvas-only overlay and add **no**
new exported primitive — so there is no new `data-role` to mirror in
`renderDrawingSvg.ts`. Grep-parity check is satisfied by construction.

## 7. Edge cases

- **Empty clip** (center dragged fully off geometry): `projectDetailView` returns
  empty edges + `{0,0,0,0}` bbox; detail renders empty; no throw. Allowed.
- **Min radius:** resize clamps to `MIN_DETAIL_RADIUS_MM`; cannot reach zero/negative.
- **Esc mid-drag:** reverts live preview to `startRegion`, no command pushed.
- **Undo/redo:** `EditDetailRegionCommand` round-trips region+projection+fingerprint.
- **Parent without projection:** mode interactions are no-ops (guarded).
- **Multiple details on one parent:** each callout gets its own handle set; drag
  targets the specific `detailViewId` from the handle's `onPointerDown`.
