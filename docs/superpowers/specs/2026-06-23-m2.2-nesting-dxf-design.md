# M2.2 — Nesting / Sheet-Layout DXF Export — Design

**Date:** 2026-06-23
**Milestone:** M2 (manufacturing output / ABF parity) — second slice, after M2.1 per-panel manufacturing DXF.
**Branch:** `feat/m2.2-nesting-dxf` off `master`.

## Goal

From the Furniture → Nesting ribbon, export the current nest result
(`activeAssembly.nest`) as a ZIP of DXF files — **one DXF per sheet**, each a
true-millimetre cut layout: the stock boundary plus every placed panel as a
cut-path rectangle with a label. This is the DXF sibling of the existing
per-sheet PNG export (`ExportNestPngCommand`) and the all-sheets PDF export
(`ExportNestPdfCommand`).

## Context / reused seams

All inputs already exist — no recomputation:

- **Nest result** lives in `activeAssembly.nest: NestState`
  (`packages/shared/src/nesting/nestState.ts`).
  - `NestState.sheets: NestSheet[]`, each
    `{ materialId, sheetIndex, sheetLengthMm, sheetWidthMm, panels: PlacedPanel[], utilizationPct }`.
  - `PlacedPanel` = `{ itemNumber, rowKey, x, y, length, width, rotated }`.
- **DXF primitives** — `createDxfDocument` (`packages/.../drawing/dxfWriter.ts`)
  exposes `lwpolyline`, `text`, `line`, `toString`, etc. Manufacturing layer
  names live in `packages/.../drawing/manufacturingLayers.ts`
  (`MANUFACTURING_LAYERS`).
- **Zip** — `buildDxfZip(entries: Record<string, string>): Uint8Array`
  (`packages/.../drawing/dxfZip.ts`).
- **Existing nest exports to mirror** — `ExportNestPngCommand`,
  `ExportNestPdfCommand`, and the M2.1 `ExportPanelManufacturingDxfCommand`
  (`showSaveFilePicker` + `<a>` download fallback pattern).
- **Preview reference** — `SheetSvg.tsx` draws the same layout as SVG (sheet
  outline, panel `<rect>`s labelled `#item`, dims). The DXF output should
  visually match it (minus grain arrows).

## Architecture — three new units

### 1. `renderNestSheetDxf(sheet, meta): string`
`packages/.../drawing/renderNestSheetDxf.ts`

- Signature: `renderNestSheetDxf(sheet: NestSheet, meta: { sheetCount: number; materialName: string }): string`.
- 1:1 millimetres, no scaling (parallels `renderDrawingDxf1to1`).
- Emits onto three layers:
  - **`SHEET`** — one closed LWPOLYLINE for the stock boundary:
    `(0,0) → (sheetLengthMm,0) → (sheetLengthMm,sheetWidthMm) → (0,sheetWidthMm)`.
  - **`OUTLINE`** — one closed LWPOLYLINE per `PlacedPanel`. Rectangle anchored
    at `(panel.x, panel.y)`. **Footprint accounts for `rotated`:** drawn width =
    `rotated ? panel.width : panel.length`; drawn height =
    `rotated ? panel.length : panel.width`. (i.e. `rotated` swaps the placed
    footprint — confirm against `packGuillotine` placement convention during
    implementation and pin a test.)
  - **`INFO`** — per-panel TEXT `#<itemNumber>  <L>×<W>` centred in the panel
    rect; plus one header TEXT near the top: `Sheet <sheetIndex+1>/<sheetCount> · <materialName> · util <utilizationPct>%`.
- Returns `doc.toString()`.
- Add a `sheet: 'SHEET'` key to `MANUFACTURING_LAYERS` (reuse existing
  `outline: 'OUTLINE'`, `info: 'INFO'`).

### 2. `ExportNestDxfCommand`
`packages/.../commands/ExportNestDxfCommand.ts`

- Ctor: `{ nest: NestState; suggestedName: string }`.
- `apply()`: a pure helper `buildNestZipEntries(nest)` iterates `nest.sheets`,
  calls `renderNestSheetDxf` per sheet, keys each entry
  `${materialId}-sheet-${sheetIndex + 1}.dxf` → `buildDxfZip` →
  `showSaveFilePicker` with `<a>` download fallback (copy
  `ExportPanelManufacturingDxfCommand` exactly).

### 3. Button — `FurnitureTab.tsx`
- In the existing Nesting `RibbonPanel` (~line 558, next to "Export PDF").
- Gated `disabled={!activeAssembly?.nest}` (must Generate Nest first).
- `onClick` → `new ExportNestDxfCommand({ nest: activeAssembly.nest, suggestedName: `${activeAssembly?.name ?? 'assembly'}-nest.zip` }).apply()`.
- i18n key `ribbon.furniture.nesting.exportDxf` — add to **en + uk** locales.

## TDD slices (red → green → refactor)

1. **`renderNestSheetDxf` unit** — given a `NestSheet` with N panels (incl. one
   `rotated`), assert: SHEET boundary present at correct mm; N panel LWPOLYLINEs
   on `OUTLINE`; rotated panel footprint swapped; N `#item L×W` labels + 1 header
   on `INFO`. Oracle for the rotated-swap geometry comes from `packGuillotine`'s
   placement math, **not** the renderer's assumption (M2.1 lesson #2).
2. **`buildNestZipEntries` / `ExportNestDxfCommand` unit** — nest of M sheets →
   exactly M entries, keyed `${materialId}-sheet-K.dxf`, each a non-empty DXF
   string containing the three layers.
3. **e2e** (`tests/e2e/drawing/`) — generate a nest, invoke
   `ExportNestDxfCommand`, unzip, assert per-sheet DXF contains `SHEET`,
   `OUTLINE`, `INFO` layer refs and the expected panel count. (Direct command
   invocation, mirroring the M2.1 e2e; button-click glue is unit+review only.)

**Gate after EVERY task:** `pnpm typecheck` (M2.1 lesson #1 — a struct-vs-string
type bug rode 3 tasks with no per-task tsc gate). Plus the relevant vitest suite.

## Out of scope (YAGNI)

- Machining (bores/grooves) inside panel rectangles — that is M2.1's per-panel
  DXF; a future M2.x could merge the two into a nested CNC program.
- Grain-direction arrows, explicit kerf lines (kerf shows as natural gaps),
  combined single-DXF / tiled output, per-material grouping.
