# Формати файлів

> Чотири власні типи файлів, які Zilventor читає й записує, їхня поточна версія формату та що відбувається під час відкриття старішого файлу.

Кожен документ протягом сесії живе у сховищі браузера [OPFS](./glossary.md#opfs) і зберігається в один із чотирьох власних форматів. Три з них (деталь, збірка, креслення) мають спільну схему маніфесту та єдиний лічильник версій; формат шаблону аркуша — окрема, самостійно версіонована обгортка.

## Власні формати

| Розширення | Тип документа | `kind` маніфесту | Тип accept для збереження/експорту |
|---|---|---|---|
| `.zipt` | Деталь | `'part'` | `application/zilinventor-part` |
| `.ziasm` | Збірка | `'assembly'` | `application/zilinventor-assembly` |
| `.zidw` | Креслення | `'drawing'` | `application/zilinventor-drawing` |
| `.zitpl` | Шаблон аркуша (шаблон основного напису/рамки креслення) | — (не є частиною системи маніфестів, див. нижче) | — |

Файли `.zipt`, `.ziasm` та `.zidw` — це tar.gz-архіви, що містять `manifest.json` (з полями `formatVersion`, `kind`, `createdAt`, `appVersion` та корисним навантаженням `document`), плюс будь-яку вбудовану геометрію/ресурси. `.zitpl` — звичайний JSON-файл у UTF-8 з власним полем `formatVersion` (наразі `1`) — він не мігрується механізмом, описаним нижче, і кругообіг відбувається лише всередині цього застосунку.

## Поточна версія формату

**`CURRENT_FORMAT_VERSION = 41`** для схеми маніфесту деталі/збірки/креслення.

## Міграція під час відкриття

Відкриття будь-якого файлу `.zipt`, `.ziasm` чи `.zidw` **автоматично й без попереджень мігрує його в пам'яті** до поточної версії — без діалогу, без запиту та без можливості відмовитись. Кожен крок версії з таблиці нижче застосовується по порядку між збереженою у файлі `formatVersion` та 41. Міграція існує лише в пам'яті: файл на диску **не** перезаписується, доки ви наступного разу явно його не збережете. Відкриття файлу, чия `formatVersion` *новіша* за `CURRENT_FORMAT_VERSION` застосунку, завершується помилкою замість тихого пониження версії — це трапляється, якщо ви відкриваєте файл, збережений новішою збіркою застосунку.

Більшість кроків — адитивні no-op-и (з'являється нове необов'язкове поле, а наявні документи його просто ще не мають); лише кілька кроків активно переписують дані. Повна історія версій:

| Версія | Що змінилося |
|---|---|
| 1→2 | Синтезувати ID примітивів для елементів ескізу. |
| 2→3 | Додати залежності до елементів ескізу, виведені з наявної геометрії. |
| 3→4 | Гарантувати наявність `document.parameters`. |
| 4→5 | Додати поле `operation` (new/join) до елементів витягування. |
| 5→6 | Адитивно — елемент спряження. |
| 6→7 | Адитивно — елемент зсуву по траєкторії. |
| 7→8 | Схема збірки: шляхи компонентів замінюють голі ID компонентів у залежностях; перейменування закріплених компонентів. |
| 8→9 | Адитивно — набір iProperty у документах деталі/збірки. |
| 9→10 | Адитивно — список матеріалів. |
| 10→11 | Адитивно — номери позицій розкрою. |
| 11→12 | Адитивно — список каталогу фурнітури; додає вбудовані записи фурнітури. |
| 12→13 | Адитивно — поля розкладки/розміру аркуша (до цього лише для запису). |
| 13→14 | Адитивно — тип документа «креслення». |
| 14→15 | Адитивно — переріз (Section View). |
| 15→16 | Адитивно — виносний елемент (Detail View). |
| 16→17 | Адитивно — розриви виду розриву (broken view). |
| 17→18 | Заповнити заднім числом поле `mode` для наявних перерізів. |
| 18→19 | Заповнити заднім числом поле `kind` для наявних зон виносних елементів. |
| 19→20 | Адитивно — власні текстури (PBR-матеріали). |
| 20→21 | Адитивно — присадка панелей, необов'язкова роль компонента. |
| 21→22 | Адитивно — специфікація дверей на екземплярах компонентів. |
| 22→23 | Адитивно — поля редагування присадки/напрямку з'єднання, список заблокованих з'єднувачів. |
| 23→24 | Адитивно — специфікація шухляди, присадка напрямних шухляди. |
| 24→25 | Адитивно — присадка під гвинт ручки, роль ручки шухляди. |
| 25→26 | Адитивно — ролі панелей стояка/поперечки лицьової рамки. |
| 26→27 | Кромки отримують обов'язкову товщину; наявні кромки заповнено заднім числом значенням 0.4мм. |
| 27→28 | Адитивно — порожній список правил (параметричний конфігуратор). |
| 28→29 | Адитивно — порожній список заблокованих елементів. |
| 29→30 | Адитивно — порожній список конфігурацій (iPart). |
| 30→31 | Адитивно — примітив ескізу «еліпс»; розширено ступінь сплайна. |
| 31→32 | Адитивно — примітив ескізу «точка», анотації ескізу. |
| 32→33 | Адитивно — поле власного каталогу фурнітури. |
| 33→34 | Адитивно — контур елемента панелі (кутові шафи). |
| 34→35 | Адитивно — метадані CAM для присадки/пазів. |
| 35→36 | Адитивно — тип матеріалу, ціни за одиницю збірки. |
| 36→37 | Адитивно — тип елемента «шип/гніздо». |
| 37→38 | Адитивно — індекс екземпляра розкладки/прапорці віддзеркалення, прапорці залишку аркуша/ручного редагування. |
| 38→39 | Адитивно — відстеження виготовлених панелей (звірка виробництва). |
| 39→40 | Адитивно — тип елемента «замковий паз». |
| 40→41 | Адитивно — поле `BoreOp.sku`. |

## Зовнішні формати

[Формати експорту](./export-formats.md) та [Імпорт і міграція](../import-migration/index.md).
