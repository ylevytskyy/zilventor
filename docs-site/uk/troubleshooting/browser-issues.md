# Проблеми браузера
> Функції лише для Chromium, вимоги до сховища та що робити, коли з'являється
> банер стану ядра/розв'язувача.

Zilventor покладається на кілька браузерних API, які підтримуються не
повсюдно. Більшість застосунку працює в будь-якому сучасному браузері, але
кілька функцій звужують поле до браузерів на основі Chromium зокрема. Див.
[Підтримка браузерів](../getting-started/browser-support.md) для загального
базового рівня сумісності.

## Функції лише для Chromium

- **Імпорт з Inventor** потребує `showDirectoryPicker` — метод File System
  Access API, який реалізовано лише в Chrome, Edge, Brave та Arc. Якщо
  кнопка неактивна або видає помилку при натисканні, ви, ймовірно,
  використовуєте Firefox чи Safari; перейдіть на браузер на основі Chromium
  для цього конкретного робочого процесу.
- **Сховище** — Zilventor зберігає ваші робочі документи в Origin Private
  File System (OPFS). Це обов'язково, а не опційно: без OPFS автозбереженню
  та відновленню сесії нема куди записувати дані. Усі поточні випуски
  Chromium і останні випуски Safari/Firefox підтримують OPFS, але якщо ваш
  браузер застарілий або працює в заблокованому/приватному режимі, що
  вимикає сховище джерела, очікуйте, що збереження мовчки не спрацюють.

## Банер «Ядро зупинено»

Якщо геометричне ядро (воркер WASM OCCT) аварійно завершується або
перестає відповідати, у рядку стану з'являється банер із текстом
**«Ядро зупинено — натисніть для перезапуску»**. Натискання на нього
завершує роботу воркера ядра, перезапускає його та повторно застосовує
історію елементів активної деталі на місці — перезавантажувати сторінку
для цього не потрібно. Якщо натискання на банер не вирішує проблему (банер
з'являється знову негайно або застосунок залишається таким, що не
відповідає), перезавантажте сторінку як останній засіб; ваша робота
захищена автозбереженням, тож перезавантаження відновить останній
автозбережений стан.

## Банер «Розв'язувач ескізу аварійно завершився»

Якщо розв'язувач залежностей 2D-ескізу аварійно завершується під час
редагування, з'являється банер із текстом **«Вирішувач ескізу аварійно
завершився — режим ескізу закрито»**, і вас викидає з режиму ескізу.
Повторно увійдіть в ескіз і повторіть редагування, яке спричинило збій —
зазвичай це одна невдала залежність або надмірно обмежена комбінація
геометрії. Якщо збій повторюється на тому самому ескізі, спростіть
залежності перед повторною спробою або перезавантажте сторінку, якщо ескіз
залишається нередагованим.

## Файли SolidWorks не імпортуються напряму

Zilventor виявляє файли `.sldprt` та `.sldasm` при відкритті й показує
діалог із вказівками замість спроби їх імпортувати — власний формат
SolidWorks не підтримується. Спочатку експортуйте файл у STEP із
SolidWorks, а потім імпортуйте файл STEP. Див.
[SolidWorks-файли](../import-migration/solidworks-files.md).
